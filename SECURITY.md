# Security policy

Do not report suspected vulnerabilities, credentials, private data, or exploit details in a public issue, discussion, or pull request.

Use the affected repository's **Security** tab to submit a private vulnerability report. Include:

- the affected repository and exact revision or release;
- the security impact and realistic threat scenario;
- the smallest safe reproduction;
- affected configurations or platforms;
- any known mitigation or workaround.

When private vulnerability reporting is unavailable, contact an organization owner through a non-public channel and identify the affected repository. Do not include more sensitive detail than is necessary to establish contact.

Supported versions, response targets, embargoes, and disclosure timing remain repository-specific until a project publishes a release policy. Security fixes must minimize unnecessary disclosure, preserve evidence, and pass the affected repository's validation and release gates.
