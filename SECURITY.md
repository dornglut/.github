# Security policy

Do not report suspected vulnerabilities in a public issue.

Use the affected repository's **Security** tab to submit a private vulnerability report. Include the affected revision or release, impact, reproduction details, and any known mitigation. When private reporting is unavailable, contact an organization owner through a non-public channel and identify the affected repository.

Supported versions and disclosure timing are repository-specific until a project publishes a release policy. Security fixes must preserve evidence, minimize unnecessary disclosure, and pass the affected repository's validation and release gates.
