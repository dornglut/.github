# Support

Use the affected repository's issue tracker for reproducible defects and concrete proposals when that repository enables them.

Before opening an issue:

- search existing issues and pull requests;
- identify the repository, revision, platform, and relevant configuration;
- provide the smallest useful reproduction or concrete problem statement;
- distinguish a usage question from a defect, proposal, or security report;
- remove credentials and private data from all public evidence.

Undeveloped ideas should remain private until they can identify a useful problem or possibility. Organization maintainers capture such ideas in the private Dornglut Inbox rather than creating speculative public issues.

Cross-repository governance and architecture proposals belong in `dornglut/engineering`. Product behavior belongs in the repository that owns it.

Security reports must follow [SECURITY.md](SECURITY.md). Dornglut does not currently provide guaranteed response times, service-level commitments, or private product support.
